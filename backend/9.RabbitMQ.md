# RabbitMQ

高性能的异步通信组件

### 1、异步调用的优势：

- 解除耦合，拓展性好
- 无需等待，性能好
- 故障隔离
- 缓存消息，流量削峰填谷

### 2、异步调用的缺点：

- 不能立即得到结果，时效性差
- 不能确定下游业务是否成功
- 业务安全依赖于 broker 的可靠性

### 3、mq 技术选型：

- RabbitMQ
- Kafka
- RocketMQ

### 4、RabbitMQ 整体架构

- virtual-host: 虚拟主机，一个虚拟主机代表一个独立的消息队列，可以隔离不同业务之间的消息，避免消息冲突
- publisher: 发布者，向消息队列发布消息
- consumer: 消费者，从消息队列中获取消息
- exchange: 交换机，消息队列的交换器，消息生产者将消息发送给交换机，交换机根据路由规则将消息发送给对应的消息队列
- queue: 消息队列，消息生产者将消息发送给交换机，交换机根据路由规则将消息发送给对应的消息队列

### 7、java 客户端

引入依赖

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-amqp</artifactId>
</dependency>
```

配置 mq 连接数据

```yml
spring:
    rabbitmq:
        host: 192.168.56.101
        port: 5672
        username: hmall
        password: 123456
        virtual-host: hmall
        listener:
            simple:
                prefetch: 1
```

发消息

```java
@SpringBootTest
public class SpringAmqpTest {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    @Test
    public void testSendMessage() {
        rabbitTemplate.convertAndSend("hello.queue1", "hello hmall");
    }
}
```

接受消息

```java
@Component
@Slf4j
public class SpringRabbitListener {
    @RabbitListener(queues = "hello.queue1")
    public void listenHelloQueue(String msg) {
        log.info("hmall 接收到消息：{}", msg);
    }
}
```

### 10、Direct 交换机

接收到的消息根据路由指定的Queue，称为定向路由

- 每个 queue 都与 exchange 设置一个 bindingkey
- 发布者发送消息时，指定 消息的 routingKey
- exchange 将消息路由到 bindingkey 和 routingKey 一致的队列

### 11、Topic 交换机

与 direct 相似，区别在于 routingKey 可以是多个单词的列表，以 `,` 分割。

queue 与 exchange 指定 bindingkey 的时候，可以指定通配符，如：

- `#`：匹配一个或多个词
- `*`：匹配一个词

### 12、声明队列交换机

如何通过代码来实现mq，而不是通过可视化界面配置？

在消费者模块下实现 bean 的注入

```java
@Configuration
public class FanoutConfiguration {

    // 交换机的定义
    @Bean
    public FanoutExchange fanoutExchange() {
        // ExchangeBuilder.fanoutExchange("hmall.fanout2").build();
        // or 两者都可以
        return new FanoutExchange("hmall.fanout2");
    }

    // 队列的定义
    @Bean
    public Queue fanoutQueue3() {
        QueueBuilder.durable("ff").build();
        // or 两者都可以
        return new Queue("hmall.fanout.queue3");
    }

    @Bean 
    public Binding fanoutBinding3() {
        return BindingBuilder.bind(fanoutQueue3()).to(fanoutExchange()); // 传参也可以，直接调用方法也行
    }
}
```

上面的写法过于麻烦重复

```java
@Component
public class FanoutListener {

    @RabbitListener(bindings = @QueueBinding(
        value = @Queue("direct.queue1", durable = "true"),
        exchange = @Exchange(value = "direct.exchange", type = ExchangeTypes.DIRECT),
        key = { "red", "blue" }
    ))
}
```

### 13、消息转换器

需求：测试利用 springAMQP 发送对象类型消息，查看问题。

对消息对象的处理是由 org.springframework.amqp.support.converter.MessageConverter 实现的。而默认实现是 SimpleMessageConverter。

基于 JDK 的ObjectOutputStream 完成序列化的。

存在的问题：

- JDK 序列化由安全风险
- JDK 序列化消息太大
- JDK 序列化消息可读性差

解决方案就是引入 jsckson 依赖。

```xml
<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
</dependency>
```

在publisher 和 consumer 中配置 MessageConverter: 

```java
@Bean
public MessageConverter messageConverter() {
    return new Jackson2JsonMessageConverter();
}
```
