# 原理篇

## 一、bean 管理

### 1、bean 的获取

默认情况下，springboot 启动会把 bean 都创建好放到 ioc 容器中，如果想要主动获取这些 bean，可以通过：

- 根据name 获取 bean
- 根据类型获取 bean
- 根据 name 获取 bean (带类型转换)

```java
class SpringbootConfigApplicationsTest {

    @Autowired
    private ApplicationContext applicationContext;

    public void testGetBean() {

        // 根据 bean 的名称获取
        DeptController bean1 = (DeptController) applicationContext.getBean("deptController");

        // 根据 bean 的类型获取
         DeptController bean2 = (DeptController) applicationContext.getBean(DeptController.class);

        // 根据 bean 的名称及类型获取
         DeptController bean3 = (DeptController) applicationContext.getBean("deptController", DeptController.class);

    }
}
```

### 2、bean 的作用域

- singleton：单例，默认，容器内同名称的 bean 只有一个实例
- prototype：多例，容器内同名称的 bean 每次获取都会创建一个新的实例
- request：每次请求都会创建一个新的实例
- session：每次会话都会创建一个新的实例
- globalSession：全局会话，每次全局会话都会创建一个新的实例

```java
@Lazy（延迟注入，当第一次使用时，菜注入）
@Scope('prototype')
@RestController
@RequestMapping("/dept")
public class DeptController {}
```

### 2、自动配置原理

方案一：

`@ComponentScan({"", ""})` 来扫描第三方的 bean 实现 自动注入

方案二：

`@import 导入`

导入普通类 @import(TokenParser.class)

```java
@Component
public class TokenParser {
    public void parse() {}
}
```

导入配置类 @import(HeaderConfig.class)

```java
@Configuration
public class HeaderConfig {

    @Bean
    public HeaderParser headerParser() {
        return new HeaderParser();
    }
}
```
  
导入 ImportSelector 接口实现类

```java
public class HeaderImportSelector implements ImportSelector {
    public String[] selectImports(AnnotationMetadata annotationMetadata) {
        return new String[]{"con.example.HeaderConfig", ""};
    }
}
```

@EnabledHeaderConfig 注解

第三方帮我们封装的注解，需要自己写一个类，实现 ImportSelector 接口，返回需要导入的类
