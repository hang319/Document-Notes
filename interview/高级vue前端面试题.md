#### 1、Vue 的虚拟 DOM 是什么？它的优缺点有哪些？

虚拟 DOM（Virtual DOM）是用 JavaScript 对象模拟真实 DOM 结构的一种技术。Vue 在渲染时会先生成虚拟 DOM，然后通过 diff 算法比较新旧虚拟 DOM 的差异，最后只将变化的部分更新到真实 DOM 上。

**优点：**
- 提高性能：减少直接操作真实 DOM 的次数，批量更新，提升渲染效率。
- 跨平台：虚拟 DOM 不依赖浏览器，可以用于服务端渲染、Weex、小程序等多端。
- 更好的编程体验：用数据驱动视图，开发者只需关注数据和状态。

**缺点：**
- 存在性能损耗：对于简单静态页面，虚拟 DOM 的 diff 和 patch 过程反而比直接操作真实 DOM 慢。
- 不是银弹：极端复杂场景下，手动优化真实 DOM 可能更高效。

**总结：**
虚拟 DOM 适合大多数前端开发场景，能带来更高效的开发体验和良好的性能，但也要根据实际需求选择是否使用。

#### 2、Vue 的响应式原理是什么？说说 Object.defineProperty 和 Proxy 的区别。

Vue 的响应式原理是通过劫持数据的读写操作，实现数据和视图的自动同步。Vue2 主要使用 Object.defineProperty 对对象的属性进行数据劫持，Vue3 则采用了 Proxy 实现更强大和灵活的响应式。

**Object.defineProperty（Vue2）**
- 只能劫持对象的已有属性，新增/删除属性无法被监听。
- 需要递归遍历对象的每个属性，性能较低。
- 无法直接监听数组的索引和长度变化，只能通过重写数组方法实现。

**Proxy（Vue3）**
- 可以直接监听整个对象，包括新增、删除属性等操作。
- 支持数组、Map、Set 等更多数据结构的劫持。
- 性能更高，语法更简洁，API 更强大。

**总结：**
Vue2 的响应式基于 Object.defineProperty，存在一些局限性；Vue3 基于 Proxy，解决了 Vue2 的缺点，实现了更彻底的响应式系统。

### 3、什么是执行上下文

- JavaScript 中运行的任何代码都是在执行上下文中运行的
- 当前 JavaScript 代码被执行和解析时所在环境(抽象概念)

有几种执行上下文的类型

- 全局执行上下文： window
- 函数执行上下文: this
- Eval 全局执行上下文: 不用考虑

什么是 执行上下文栈

- 执行上下文栈可以类似于一个存储函数调用的栈结构，遵循先进后出的原则。
- JavaScript 执行在单线程上，所有代码都是排队执行。
- 处于活动状态的执行上下文环境只有一个，且位于栈顶。
- 函数执行上下文执行完毕就会出栈，等待垃圾回收
